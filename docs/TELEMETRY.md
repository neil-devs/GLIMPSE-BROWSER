# Glimpse Browser — Telemetry Architecture & Data Dictionary

## 1. Privacy by Design Principles

Glimpse Browser collects search and prefetch timing metrics solely to train and evaluate the link prefetch ML model (`click-predictor`). Telemetry is engineered with strict privacy boundaries:

1. **Zero Raw Query Storage**: Raw search query text is **never** sent to the cloud or saved to disk. Queries are processed on-device via `computeQueryFeatures()`, producing only coarse statistical counts (word count, character length bucket), script classification (latin, cjk, cyrillic, other), and high-level intent flags (informational, transactional, code, etc.).
2. **Zero Full Destination URLs**: Only destination domain names and top-level domains (e.g. `github.com`, `wikipedia.org`) are recorded. Complete URL query parameters and paths are discarded.
3. **Hardware-Independent Identity**: The `install_id` is a purely random UUID v4 generated locally and persisted in `local_settings`. It is never derived from MAC addresses, CPU IDs, or hardware identifiers.
4. **Strict Consent Gating**:
   - Nothing is recorded, queued, or transmitted unless user consent is explicitly set to `granted`.
   - The environment variable `TELEMETRY_ENABLED=false` acts as an absolute kill switch.
   - Setting `GLIMPSE_TELEMETRY_DEBUG=1` dumps payloads to local logs without making network calls.
5. **Right to Be Forgotten**: Users can trigger "Delete my telemetry data" from Settings or via `DELETE /telemetry/data`. This drops all remote records for that `install_id`, clears the local SQLite queue, and rotates the local install ID.

## 2. Desktop Queue & Transmission (`telemetry-queue.js`)

- **Storage**: Persistent SQLite table `telemetry_queue (id, payload, created_at, attempts, next_attempt_at)`.
- **Capacity**: Maximum 5,000 records. If the queue overflows, the oldest records are dropped FIFO.
- **Flush Cadence**: Periodically every 20 seconds and on application shutdown (best effort).
- **Batching**: Up to 50 sessions per HTTP request (`POST /telemetry/batch`).
- **Resilience**: Exponential backoff with random jitter (`2^attempts * 10s + jitter`, max 1 hour).
- **Security**: Requires HTTPS in production (HTTP is only permitted for localhost during development).
- **Timeouts**: 5-second AbortController timeout per network attempt.

## 3. Data Dictionary

### 3.1 `search_events`
| Field | Type | Description |
|---|---|---|
| `id` | UUID (PK) | Server-generated primary key |
| `install_id` | UUID | Random anonymous install identifier |
| `client_event_id` | UUID (Unique) | Client-generated ID for idempotent ingestion |
| `search_engine` | ENUM | `google`, `bing`, `duckduckgo`, `yahoo`, `baidu`, `yandex` |
| `query_text` | NULL | Always null in Telemetry V2 (privacy rule) |
| `query_length` | SMALLINT | Character length of the query |
| `query_features` | JSONB | Coarse flags: `{ length, wordCount, hasDigit, hasYear, isQuestion, hasSiteOperator, script, intent }` |
| `model_version` | VARCHAR(20) | Active prefetch model version (e.g. `v2.0.0`) |
| `app_version` | VARCHAR(20) | Desktop application version |
| `result_count_visible` | SMALLINT | Count of visible search results in viewport |
| `window_width` | SMALLINT | Browser window inner width in pixels |
| `window_height` | SMALLINT | Browser window inner height in pixels |
| `is_synthetic` | BOOLEAN | `true` if generated by the simulator, `false` for real traffic |
| `searched_at` | TIMESTAMPTZ | Timestamp of the search event |

### 3.2 `result_link_events`
| Field | Type | Description |
|---|---|---|
| `id` | UUID (PK) | Server-generated primary key |
| `search_event_id` | UUID (FK) | Reference to parent `search_events.id` |
| `client_event_id` | UUID (Unique) | Client-generated link impression ID |
| `domain` | VARCHAR(255) | Destination hostname (e.g. `en.wikipedia.org`) |
| `tld` | VARCHAR(24) | Top-level domain (e.g. `org`) |
| `url_depth` | SMALLINT | Number of URL path segments |
| `link_text_length` | SMALLINT | Character length of anchor text |
| `link_position` | SMALLINT | 1-based rank position on the results page |
| `was_visible_on_load` | BOOLEAN | `true` if link was visible in viewport without scrolling |
| `first_visible_ms` | INTEGER | Time in ms from page load until link intersected viewport |
| `preload_state` | VARCHAR(12) | `none`, `loading`, `ready`, `failed` |
| `model_score` | REAL | ML predicted probability of click (0.0 to 1.0) |
| `model_rank` | SMALLINT | Rank assigned by model score sorting |
| `was_clicked` | BOOLEAN | Whether the link was clicked |
| `click_class` | VARCHAR(24) | `HIT_READY`, `HIT_LOADING`, `MISS_NOT_POOLED`, `MISS_FAILED` |
| `ms_to_usable` | INTEGER | Milliseconds from click to usable page render |
| `is_synthetic` | BOOLEAN | `true` if generated by simulator |
| `created_at` | TIMESTAMPTZ | Record timestamp |

### 3.3 `model_field_stats`
Aggregated daily top-1/3/6 hit rates reported by client installations:
| Field | Type | Description |
|---|---|---|
| `install_id` | UUID | Client installation ID |
| `model_version` | VARCHAR(20) | Model version being evaluated |
| `day` | DATE | Date of metric aggregation |
| `searches` | INTEGER | Total searches performed on that day |
| `hits_top1` | INTEGER | Searches where user clicked the model's #1 ranked result |
| `hits_top3` | INTEGER | Searches where user clicked within model's top 3 results |
| `hits_top6` | INTEGER | Searches where user clicked within model's top 6 results |
| `baseline_hits_top3` | INTEGER | Searches where user clicked within position rank 1..3 |

## 4. API Endpoints

- `POST /telemetry/batch`: Ingests an array of up to 50 search sessions (limit 256 KB). Idempotent via `client_event_id`.
- `DELETE /telemetry/data`: Deletes all search events, cascaded link events, and field stats for a given `installId`.
- `GET /admin/telemetry/summary`: Requires `X-Admin-Key` header verified with constant-time `timingSafeEqual`. Returns system-wide metrics across engines, click classes, and dates.
